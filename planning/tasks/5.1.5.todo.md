## Notes
- Analysis (read-only, done):
  - `geodesic_kde_rust` (lib.rs:44-149): `let mut sum = 0.0;` at line 107, `visit` closure adds `exp(-0.5*(d/bw)^2)` when `d < 3*bw` (lines 113-116), closure returns `sum` at line 144. Bandwidth is the function argument `bandwidth_km` (fixed). `densities` is collected at lines 102-146, returned at 148.
  - `geodesic_kde_adaptive_rust` (lib.rs:172-303): `let mut sum = 0.0;` at line 262, `visit` at 263-271, returns `sum` at line 298. Bandwidth is the per-cell `bandwidth_km` from the `.zip(scales.par_iter())` destructuring at line 260. Output collected at lines 256-300, returned at 302.
  - `n`: both functions take `x_coords: Vec<f64>`, so `x_coords.len()` is available before the `x_coords` clone or move. `data_points` is built from it; `n` equals `data_points.len()`. `bandwidth_loocv_evaluate` already uses `let n_points = x_coords.len();` (line 323), the same pattern.
  - Test helpers (inst/tinytest/test_geodensity.R:469-488): `bf_fixed(x, y, gx, gy, bw)` returns `sum(exp(-0.5*(d/bw)^2))` over `d < 3*bw`, so unnormalized. `bf_adaptive(x, y, gx, gy, pilot, min_bw)` calls `bf_fixed` for the pilot, builds `scale` per cell, then returns the unnormalized per-cell sum over `d < 3*scale[i]`. `bf_expect(res, ref, info)` at 491-496 uses relative error with an exact-zero branch, at 1e-10.
- Division site: after `.collect()`, not inside the closure. Either a `.map` on the `par_iter` output or a second loop. Recommend one division per output element, using the per-cell scale in the adaptive path.
- Normalization in the reference: fixed reference `bf_fixed(...) / (2*pi*bw^2*n)`, adaptive reference `bf_adaptive(...)[i] / (2*pi*scale[i]^2*n)`. The adaptive helper computes `scale` internally and does not return it. So either (a) add a helper variant that returns both the normalized density and scale, or (b) recompute `scale` in the test by the same formula. Option (a) is cleaner and keeps the case inputs unchanged.
- Consistency check: `bf_adaptive` computes `scale` with `sqrt(ratio)`. Rust uses `density_ratio.powf(0.5)`. These match. The pilot in the Rust version is normalized, but `ratio = p/dmax` is invariant to a constant factor, so the scales are unchanged. Test 5.1.2 scaling checks (lines 639-688) use the unnormalized `bf_fixed` pilot, which stays valid.
- Risks:
  - `n = 0` gives a division by zero. Check whether the R wrapper rejects empty input. If not, this is a pre-existing gap, so report it rather than widening the change.
  - Pilot normalization is harmless in theory but adds one more division. If the normalization is placed in `geodesic_kde_rust`, the adaptive pilot is normalized too. Placing it in the callers of the Rust function (kde wrappers) avoids that. Prefer the Rust kernel function only if the R wrapper path is not the one used by the adaptive pass.
  - The planar `2*pi*bw^2` factor is an approximation on the sphere, so the integral will deviate from 1. This is expected and recorded, not asserted.
  - Floating-point rounding: the normalized reference and the Rust output divide in different orders. A relative 1e-10 tolerance should absorb this, but a stop rule applies if it does not.
