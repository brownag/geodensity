**NEWS.md content plan (`# geodensity 0.2.0`):**
- New: `kde_adaptive()` adaptive-bandwidth KDE (pilot pass, per-cell bandwidth bounded by `min_bandwidth` and `pilot_bandwidth`).
- New: `bandwidth_optimize()` LOOCV bandwidth selection, with `print.bandwidth_cv`.
- Fixed: search-box correction. Neighbors were dropped at other latitudes. Fixed-bandwidth and adaptive values change; the adaptive path also changes through the pilot pass.
- Changed: KDE output is now probability density per km², dividing by `2*pi*bw^2*n`. Existing values change by that factor. For adaptive, the per-cell bw is used in the factor.
- Note: LOOCV keeps the intensity normalization `1/(2*pi*bw^2)` (no n). Its log-likelihood differs from KDE output by a constant `log(n)`; only the ranking across bandwidths is used.
- Removed: the false LOOCV parallelism claim. The LOOCV loop is serial.
- Changed: `bandwidth_cv` class is now `bandwidth_cv` only (no longer `c("bandwidth_cv", "list")`). It is still a list.
- Added: scalar validation of `bandwidth_min` and `bandwidth_max`.
- Changed: Haversine consolidation on `geo`. LOOCV scores shift by at most about 1e-6 relative.
- Known limitation: pole-enclosing grid points (search half-width at or above 90 degrees) scan all data points. That is O(n) per grid point and slow at high latitude with large bandwidths.
- Guard removals: D16 names them as a NEWS item, but the spec's minimum list does not. See Questions.
