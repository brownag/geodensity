  - Sizing: lines 189-196 (`cutoff_km` 191, `max_half_width_deg` 192-195, `index_cell_size` 196).
  - Index build: lines 198-225.
  - Consumers in closures: lines 254-263.

Closure captures in the fixed path: the `par_iter().map` closure captures `grid_index` (by ref, for `.get`), `data_points` (by ref, through `visit`), `index_cell_size` (copied f64), `cutoff_km` (copied f64), `bandwidth_km` (copied f64), and `data_points.len()`. The `visit` closure captures `data_points`, `grid_point`, `bandwidth_km`, `sum` (mutable). After the refactor, `grid_index` and `data_points` remain locals in each function, so the closure capture set is unchanged.

Float-order argument:
- `index_cell_size` is computed from the same `search_half_widths_deg` calls in the same fold order (grid_y iteration, `f64::max` fold starting at the cutoff's (0.0) half-width). Same operations, same operands, so same bits.
- Keys are `(p / cell).floor() as i32`, and wrapped keys use the same `wrapped_x / cell`. Same expressions, same results.
- The index is only read through `get`, so HashMap iteration order and hashing do not matter. Only the order within each `Vec<usize>` matters. Insertion order is preserved: points visited in index order, natural key before wrapped key. Summation in `visit` therefore runs in the same order, so `sum` is bit-identical.
- No arithmetic moves, no fused or reordered expressions, no change to the `visit` closure or the per-grid-point search loops.

Risks:
- Fixed path and adaptive path may differ in `cutoff_km` (3*bandwidth vs 3*pilot). The helper must take the cutoff, not bandwidth, to keep both call sites exact.
- Moving `visit` or the offset math into a helper would change captures and risk reordering. Keep them inline.
- `search_radius_cells` (named in the spec's Anchors) does not exist in `lib.rs`. Not a blocker: the offset computation is `ox`/`oy` at lines 117-118 and 256-257.
- Any accidental change to `.max(0.1).min(45.0)` order or to the `1.5` constant would change cell keys and possibly sums. Compare with the cmp gate.
