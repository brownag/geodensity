## Notes (facts from Analysis, risks)

- Guard confirmed at `src/rust/src/lib.rs` line 346, exact text: `if n_points == 0 || bandwidths.is_empty() {` / `return vec![];`. Matches spec.
- Only Rust-side caller: `R/geodensity.R:456` (`bandwidth_loocv_evaluate(pts[, 1], pts[, 2], bandwidths)`). `R/extendr-wrappers.R:52` is the generated `.Call` wrapper; `lib.rs:409` is the extendr_module registration. No other callers in `R/`, `src/rust/src/`, `inst/`, or `tests/`.
- Upstream guards: `R/geodensity.R:426` stops on `nrow(pts) == 0`; `n_bandwidths` is validated `>= 2` (line ~440) and `bandwidths` is built with `length.out = n_bandwidths`, so the R path cannot pass empty input.
- Behavior if the guard were removed and the empty case were reached anyway (not reachable via `bandwidth_optimize`, but reachable by calling the internal `.Call` wrapper directly):
  - `n_points == 0`: the distance loops do nothing, the map yields one `0.0 / 0.0` = `NaN` per bandwidth. No panic, but output is NaN vector instead of `numeric(0)`.
  - `bandwidths` empty, `n_points > 0`: the distance matrix is still computed (wasted O(n^2) work), then the map yields an empty vector. Same result as before.
  - Neither case panics, so the change is safe. The spec's "unreachable" claim holds for the R path.
- Risk: `make test` compiles Rust; warnings (50+ pre-existing per baseline) are not failures. Only the test summary line decides pass/fail.
